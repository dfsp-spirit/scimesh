# Offline glTF web viewer assets

This directory contains a small, **fully offline** WebGL viewer for scimesh's
glTF exports. Open `brain_viewer.html` (generated by
`examples/R/export_gltf.R`) by double-clicking it — no internet connection and
no local web server are required.

## Files

- `three.min.js`, `GLTFLoader.js`, `OrbitControls.js` — vendored **three.js**
  r147 (classic-script / UMD builds that expose the `THREE` global). We use the
  classic-script builds deliberately: modern three.js ships only ES modules,
  which browsers refuse to import from `file://` URLs (the double-click case),
  and `fetch()` of a local `.glb` is also blocked from `file://`. Classic
  scripts + an inline base64 `.glb` avoid both problems.
- `viewer_template.html` — the viewer template with `__THREE_MIN_JS__`,
  `__GLTF_LOADER_JS__`, `__ORBIT_CONTROLS_JS__`, and `__GLB_BASE64__`
  placeholders. `examples/R/gltf_to_html.R` fills them in.
- `brain_viewer.html`, `brain.glb`, `brain.gltf`, `brain.bin` — generated by
  `examples/R/export_gltf.R` (and `examples/cpp/gltf_export` for the `.glb` /
  `.gltf`). These are build outputs; regenerate them by running the example.

## Why not Google's `<model-viewer>`?

`<model-viewer>` renders a glTF scene in a single HTML tag, but it loads as an
ES module from a CDN. That requires internet and does not work from `file://`
URLs (ES-module imports are blocked there). Since the goal here is a
double-clickable, offline viewer, we vendor three.js + its classic-script
loaders instead. The generated page's source comment says the same.
